## 📖 Overview

FoodVision uses **Convex** as its primary backend, providing:
- **Real-time database** with automatic reactivity
- **Serverless functions** for business logic
- **Type-safe API** with auto-generated TypeScript types
- **File-based routing** similar to Next.js
- **Built-in authentication** integration

### Why Convex?

| Feature | Benefit |
|---------|---------|
| **Real-time Queries** | UI updates automatically when data changes |
| **Type Safety** | End-to-end TypeScript from DB to frontend |
| **Serverless** | No server management, auto-scaling |
| **ACID Transactions** | Safe data mutations |
| **File Storage** | Built-in image/file handling |
| **Scheduled Jobs** | Cron jobs for periodic tasks |

### Key Concepts

| Concept | Description | Example |
|---------|-------------|---------|
| **Query** | Read data (like GET request) | `api.Users.GetUser` |
| **Mutation** | Write/Update data (like POST/PUT/DELETE) | `api.MealPlan.CreateMealPlan` |
| **Action** | Long-running operations, HTTP endpoints | Webhook handlers |
| **Internal Mutation** | Private mutation called by other functions | `api.Slots.ensureSlots` |

## 📐 Schema Definition

### Users Table
```typescript
users: defineTable({
  name: v.string(),                    // User's full name
  email: v.string(),                   // Unique email (used for auth)
  role: v.union(                       // User role
    v.literal("user"),
    v.literal("nutritionist")
  ),
  picture: v.optional(v.string()),     // Profile picture URL
  credits: v.number(),                 // AI generation credits (default: 5)
  weight: v.optional(v.string()),      // Weight in kg
  height: v.optional(v.string()),      // Height in cm
  age: v.optional(v.string()),         // Age
  gender: v.optional(v.string()),      // Gender
  goal: v.optional(v.string()),        // Health goal
  calories: v.optional(v.number()),    // Daily calorie target
  proteins: v.optional(v.number()),    // Daily protein target
})
  .index("by_email", ["email"])        // Fast email lookup for auth
  .index("by_role", ["role"])          // Filter users by role
```

### Nutritionists Table
```typescript
nutritionists: defineTable({
  userId: v.id("users"),               // Reference to users table
  phone: v.string(),
  bio: v.string(),
  degree: v.string(),                  // Professional degree
  experienceYears: v.number(),
  specialization: v.array(v.string()), // Areas of expertise
  consultationModes: v.object({
    online: v.boolean(),
    offline: v.boolean(),
  }),
  consultationFee: v.number(),         // Fee in USD
  languagesSpoken: v.array(v.string()),
  availableSlots: v.array(v.object({   // Time slots
    date: v.string(),
    time: v.string(),
    isBooked: v.boolean(),
  })),
  isVerified: v.boolean(),
  isActive: v.boolean(),
})
  .index("by_userId", ["userId"])
  .index("by_isActive", ["isActive"])
```

### MealPlan Table
```typescript
mealPlan: defineTable({
  uid: v.id('users'),                  // User who created plan
  recipeId: v.id('recipes'),           // Recipe reference
  mealType: v.string(),                // Breakfast/Lunch/Dinner/Snacks
  calories: v.number(),                // Calories for this meal
  date: v.string(),                    // Format: DD/MM/YYYY
  completed: v.boolean(),              // Meal consumed status
})
  .index("by_uid_date", ["uid", "date"])
  .index("by_uid_date_mealType", ["uid", "date", "mealType"])
```

### Consultations Table
```typescript
consultations: defineTable({
  userId: v.id("users"),
  nutritionistId: v.id("nutritionists"),
  consultationType: v.union(
    v.literal("online"),
    v.literal("offline")
  ),
  slot: v.object({
    date: v.string(),
    time: v.string(),
  }),
  meetLink: v.optional(v.string()),
  status: v.union(
    v.literal("upcoming"),
    v.literal("completed"),
    v.literal("cancelled")
  ),
  paymentMode: v.literal("pay_on_site"),
  createdAt: v.number(),
})
  .index("by_userId", ["userId"])
  .index("by_nutritionistId", ["nutritionistId"])
  .index("by_status", ["status"])
```

## 🔄 Data Flow Patterns

### Pattern 1: Real-Time Data Fetching
```javascript
function MyComponent() {
  // Auto-updates when database changes
  const meals = useQuery(api.MealPlan.GetTodaysMealPlan, {
    uid: user._id,
    date: "04/05/2026"
  });

  if (meals === undefined) return <Loading />;
  if (meals === null) return <NotFound />;
  
  return <MealList meals={meals} />;
}
```

### Pattern 2: Optimistic Updates
```javascript
async function toggleMealComplete(mealId, completed) {
  // 1. Update UI immediately
  setLocalMeals(prev => 
    prev.map(m => m._id === mealId ? {...m, completed} : m)
  );
  
  // 2. Send to backend
  await convex.mutation(api.MealPlan.UpdateMealPlanStatus, {
    id: mealId,
    completed
  });
  // 3. UI re-renders with real data automatically
}
```

### Pattern 3: Parallel Data Fetching
```javascript
const fetchDashboardData = async () => {
  const [meals, progress, consultations, weeklyStats] = await Promise.all([
    convex.query(api.MealPlan.GetTodaysMealPlan, { uid, date }),
    convex.query(api.Users.GetUserProgress, { userId: uid }),
    convex.query(api.Consultations.getUserConsultations, { userId: uid }),
    convex.query(api.MealPlan.GetWeeklyStats, { uid })
  ]);
  
  setMeals(meals);
  setProgress(progress);
  setConsultations(consultations);
  setWeeklyStats(weeklyStats);
};
```

### Pattern 4: Data Enrichment (Joining Tables)
```typescript
// Backend - Populate related data in parallel
export const getConsultationDetails = query({
  handler: async (ctx, args) => {
    const consultation = await ctx.db.get(args.consultationId);
    if (!consultation) return null;

    const [user, nutritionist, session, preForm, expertPlan] = 
      await Promise.all([
        ctx.db.get(consultation.userId),
        ctx.db.get(consultation.nutritionistId),
        ctx.db.query("sessions")
          .withIndex("by_consultationId", q => 
            q.eq("consultationId", args.consultationId))
          .first(),
        ctx.db.query("preConsultationForms")
          .withIndex("by_consultationId", q => 
            q.eq("consultationId", args.consultationId))
          .first(),
        ctx.db.query("expertDietPlans")
          .withIndex("by_consultationId", q => 
            q.eq("consultationId", args.consultationId))
          .first(),
      ]);

    return {
      ...consultation,
      user,
      nutritionist: { ...nutritionist, user: nutritionist?.userId ? await ctx.db.get(nutritionist.userId) : null },
      session,
      preConsultationForm: preForm,
      expertDietPlan: expertPlan,
    };
  },
});
```

### Complete Booking Flow
```typescript
// 1. User browses nutritionists

// 2. Select one and view profile

});

// 3. Get available slots

  nutritionistId: selectedId,
  daysAhead: 7
});

// 4. Book consultation (slots auto-generated if needed)
const consultationId = await convex.mutation(
  api.Consultations.createConsultation,
  {
    userId: user._id,
```

### Adding a New Feature

**Step 1: Define Schema** (`schema.js`)
```typescript
newFeature: defineTable({
  userId: v.id("users"),
  data: v.string(),
  createdAt: v.number(),
})
  .index("by_userId", ["userId"])
```

**Step 2: Create API** (`NewFeature.js`)
```typescript
import { v } from "convex/values";
import { mutation, query } from "./_generated/server";

export const create = mutation({
  args: {
    userId: v.id("users"),
    data: v.string(),
  },
  handler: async (ctx, args) => {
    return await ctx.db.insert("newFeature", {
      ...args,
      createdAt: Date.now(),
    });
  },
});

export const getByUser = query({
  args: { userId: v.id("users") },
  handler: async (ctx, args) => {
    return await ctx.db
      .query("newFeature")
      .withIndex("by_userId", (q) => q.eq("userId", args.userId))
      .collect();
  },
});
```

**Step 3: Use in Frontend**
```javascript
import { api } from "../convex/_generated/api";

// Read
const data = useQuery(api.NewFeature.getByUser, { userId: user._id });

// Write
const create = useMutation(api.NewFeature.create);
await create({ userId: user._id, data: "Hello" });
```

### Best Practices

1. **Always validate inputs**
2. **Use indexes for queries**
3. **Handle errors gracefully**
4. **Use `Promise.all` for parallel operations**
5. **Never edit `_generated/` folder**
6. **Test queries in Convex Dashboard first**

## 🐛 Troubleshooting

### Common Errors

| Error | Cause | Solution |
|-------|-------|----------|
| `Index not found` | Missing index in schema | Add index in `schema.js`, restart `npx convex dev` |
| `ArgumentValidationError: extra field userId` | Passing `userId` to update mutation | Remove `userId` from update, only pass `nutritionistId` |
| `Document not found` | Invalid or deleted ID reference | Check if document exists before referencing |
| `Type error` | Schema mismatch with code | Run `npx convex dev` to regenerate types |
| `Slot not found` | Slots not generated yet | Run `ensureSlots` or wait for auto-generation |

### Debugging Tools

```bash
# View logs & test queries
npx convex dashboard

# Regenerate TypeScript types
npx convex codegen

# Reset development database

```
